# TermKrush test suite

Shared rigging for the integration tests lives under `tests/common/` and is
pulled into a test binary with `mod common;`.

## Audio fixtures (`common::fixtures`)

Synthesized, license-clean WAVs under `tests/fixtures/`, documented in
`tests/fixtures/manifest.toml` and generated by `scripts/gen-fixtures.sh`.
Reference them by typed handle:

```rust
mod common;
use common::fixtures;

let path = fixtures::HOUSE_128.path();   // 128 BPM click track
assert_eq!(fixtures::HOUSE_128.bpm, Some(128.0));
```

## Audio assertions (`common::audio`)

Readable, range-naming assertions over mono `f32` buffers in `[-1.0, 1.0]`.
Levels are dBFS (`0 dB` == peak `1.0`).

```rust
use common::audio::{assert_rms_within, assert_silent, assert_no_clicks};

assert_rms_within(&buf, -9.0, 0.2);  // RMS within 0.2 dB of -9 dBFS
assert_silent(&tail, -60.0);         // peak below -60 dBFS
assert_no_clicks(&buf);              // no adjacent-sample discontinuity
```

When a helper fails it names the offending sample (or sample range) in the
panic message, so the failure points straight at the spot in the buffer.

## Golden snapshots (`common::audio::golden_snapshot`)

Pin DSP output so a refactor that changes the samples is caught.

```rust
use common::audio::golden_snapshot;

golden_snapshot("crossfade_equal_power", &output);
```

- Snapshots are raw little-endian `f32` at `tests/golden/<name>.f32`.
- First run (or a brand-new name) writes the snapshot and passes.
- Later runs diff against it within a small epsilon; a mismatch panics
  naming the diverging sample range.
- Refresh deliberately, never silently:

  ```sh
  UPDATE_GOLDEN=1 cargo test
  ```

Review the resulting `tests/golden/` diff before committing — a changed
snapshot is a changed sound.
